# AstrBot 消息防抖插件 (`astrbot_plugin_message_debouncing`)

一款专为 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 设计的**私聊消息防抖插件**。

解决用户在聊天中习惯连续分段发送多句话（例如先发“在吗”，再发“帮我写个故事”，再发“主角叫小明”），导致机器人多次触发 LLM 并产生碎片化回复的问题。

> 本插件**只作用于私聊**。群聊消息不会被拦截、暂存或合并，群聊行为与未安装本插件时完全一致。

---

## ✨ 核心特性

- ⏱️ **智能等待与重置倒计时**：
  当检测到消息需要进行 LLM 对话时，先暂停等待指定时长（默认 5s）。若在此期间收到用户后续发言，自动重新倒计时 5s。
- 📦 **原生多模态聚合**：
  倒计时结束后，将收集到的所有消息（文本、图片、语音、文件等）合并为一条完整消息，无缝交由 AstrBot 的 LLM 处理链路。**无需插件手动区分或转码图片/文字/语音**，完全复用 AstrBot 原生多模态解析能力。
- 🔢 **严格按发送顺序合并**：
  即使后发消息先到达、先建立了防抖会话，合并时也会按消息的发送时间排序，保证喂给模型的内容与用户实际发言顺序一致。
- 🧵 **并发会话保护**：
  同一用户的连续消息可能被 AstrBot 并发处理。若两条消息都走到“准备调用 LLM”，插件会把后到的一条并入已存在的会话并阻止它单独触发回复，避免出现**一次发言收到两条回复**。
- ⚡ **指令穿透保护（无损）**：
  在防抖等待期间，如果用户发送了指令（如 `/help`、`/reset` 等），该指令**不会被当作后续消息吞掉**，会在自己的消息事件中立即执行；同时**已经缓冲的后续内容不会被丢弃**，仍会随本次对话一起交给模型。
- 🧩 **生态前置解析器无缝协同**：
  完美兼容合并转发解析插件（如 `astrbot_plugin_forward_reader_person`）、富媒体解析插件。后续消息在被防抖拦截前会自动完成前置展开；展开期间倒计时被**挂起**，且解析有超时上限，避免慢解析导致消息丢失或链路卡死。
- 🎛️ **开关与自定义时长**：
  支持私聊开关，可自定义**防抖等待时间**（默认 5.0 秒，可在 WebUI 中拖动滑动条调节）。

## ⚙️ 配置说明

在 AstrBot 管理面板（WebUI）的插件配置中，可直接调整以下参数：

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `debounce_seconds` | `float` | `5.0` | 防抖等待时间（秒）。倒计时内收到新消息将重置该时间（支持 1~60 秒范围滑动条调节）。 |
| `enable_private` | `bool` | `true` | 是否启用私聊消息防抖。关闭后插件完全不介入（群聊本来就不过问）。 |
| `preprocess_timeout_seconds` | `float` | `30.0` | **后续消息前置解析超时（秒，0=不限制）**。对后续消息执行前置解析（如合并转发读取）的最长等待；超时后仍会把消息并入缓冲（内容可能未展开），避免卡住整条链路。 |

## 🚀 工作流程

```text
[用户在私聊发送第 1 句话]
       │
       ▼
[AstrBot 管道识别需要调用 LLM]
       │
       ▼
[触发 debounce_waiting_llm 钩子] ──> 建立防抖会话（Key: 会话 + 用户）
       │
       ├──── 收到第 2 句话/图片/语音/合并转发 ──> [intercept_follow_up 捕获、重置倒计时]
       │                                          （前置展开期间倒计时挂起）
       │
       ├──── 两条消息并发走到该钩子 ──────────> [后到的一条并入已有会话，不会重复回复]
       │
       ├──── 收到指令（/help 等）────────────> [指令立即执行；已缓冲内容不丢失]
       │
       ▼
[倒计时内未再收到新消息（超时）]
       │
       ▼
[按发送时间排序，合并所有文本与消息段 (Plain/Image/Record/File)]
       │
       ▼
[交由 AstrBot 原生 LLM 链路处理] ──> 用户收到包含所有上下文的单次完整回复
```

## 📦 安装与使用

1. 将本插件目录放入 AstrBot 的插件目录：
   ```bash
   cd AstrBot/data/plugins/
   git clone https://github.com/cyilin36/astrbot_plugin_message_debouncing.git
   ```
2. 重启 AstrBot 或在 WebUI 的插件页面点击「重新加载插件」。
3. 在 WebUI 的插件配置中，按需调整防抖时间与私聊开关。

### 环境前提

- 本插件依赖 AstrBot 的 `on_waiting_llm_request` 钩子，**仅在本地 Agent（`agent_runner.runner_type = local`）链路上触发**。若使用第三方 Agent Runner，该钩子不会被调用，防抖将完全不生效。
- 私聊唤醒受 AstrBot 的 `platform_settings.friend_message_needs_wake_prefix` 影响：若开启该选项，未带唤醒前缀的私聊消息不会被唤醒，本插件也不会介入（与 AstrBot 原生行为一致）。

## 🔌 与其他插件共存

- **只过滤私聊**：拦截器的过滤器只在“私聊 + 已有防抖会话”时通过，因此群聊消息、以及本插件的非活跃期不会改变任何处理流程（包括唤醒判定）。
- **`debounce_captured` 标记**：任何被防抖捕获的后续消息都会带上 `event.set_extra("debounce_captured", True)`。其他插件可据此判断“这条消息是被合并的片段，不应作为独立样本处理”。
- **合并转发读取类插件**（如 `astrbot_plugin_forward_reader_person`）：后续消息在被拦截前会先执行其展开逻辑，展开期间倒计时挂起，展开结果随消息一起合并；不会重复展开。
- **学习/记忆类插件**（如 `astrbot_plugin_self_learning`）：如果对方是“每条消息独立入库 + 按时间前后配对”的采集方式，防抖会把 N 条分段消息合成 1 次模型输入和 1 条回复，导致其 fewshot 情境配对错位（`situation` 只对应最后一段碎片）。建议让其改为“相邻同一发送者的消息合并后再配对”。
